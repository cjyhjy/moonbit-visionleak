# 0.9.0 实施计划与验收标准

状态：开发进行中，主要工程能力及公开评测已有本地证据；当前发布版仍为 0.8.0。

## 阶段与交付

1. S1：在现有 --cache 下缓存 ORB 特征及方向检查结果。键绑定文件摘要、采样像素、profile、worker、Python/OpenCV/NumPy/build。缓存模式每次配对仅装载两张图；已完成的无命中也保留。先保留 512 张硬上限。
2. S2：明确每次调用预算与累计覆盖，提供更大输入的磁盘分批调度；覆盖跨批次关系。引入运行清单、进度与容量限制，完成 100/1000/5000 张普通照片规模阶梯后才调整硬上限。
3. S3（与 S1/S2 同期启动）：独立候选召回实验。穷举 ORB 作小规模对照，先验证描述子聚合召回方案；记录候选数量、索引内存、构建时间、查询时间与漏召回。通过后才决定产品集成。
4. S4（同期启动）：新来源冻结协议、来源排除清单与数据清单；新来源受控裁切、重复纹理难负例、自然污染分别统计。未取得自然污染真值和参与者时保持未验证状态。
5. S5：doctor、跨次复核迁移、批量复核与候选聚合；Investigator 独立迁移，接入宿主 ORB，识别预算/停止原因。

## 验收门槛

- 缓存：冷/热及禁用缓存命中、矩阵、内点和特征摘要一致；输入、profile、依赖变化失效；损坏缓存重算；原子写入；缓存不作为可信来源证明。命中仍检查当前源文件摘要和输入预算。
- 恢复：小预算多次运行最终配对集合等同足预算连续运行；必须复用无命中和第一方向无命中的工作。杀进程后已提交记录有效，未完成工作允许重做。每次调用计费与复用计数分开；不能静默扩大候选输出上限。
- 分批：跨批次命中不丢；输出顺序不变；驻留特征数有界；报告图片提取覆盖、配对处理覆盖和停止原因。先在现有上限验证，突破上限需 S2 验收。
- 检索实验：冻结参数后新来源测试；相对穷举 ORB 的召回率、端到端产品效果分别报告。预设试验准入目标：比较量减少 >=10 倍，已知正例召回 >=99%；样本数量与置信区间一起报告，未达标保留负面结果。
- 规模：100/1000/5000 张真实尺寸照片，冷/热/恢复分别记录时间、特征提取/匹配时间、磁盘量、主进程及 worker RSS；默认阈值与明确标注的实验配置并列。目标环境和可接受时限在测量前冻结。
- 效果：按来源隔离开发/保留集；真值子集报告 TP/FP/FN、覆盖率。自然数据只复核输出候选时仅报告候选精确率，不能估计整体召回率。真人记录有效发现数、图片对数、有效操作时间及总耗时。
- 回归：现有 Node、MoonBit 三后端、ORB 冻结同平台回放、报告身份与复核/导出合同通过；完整 Linux 与发布包验证在发布前完成。

## 当前边界

S1 的可恢复扫描采用内容寻址的已完成工作复用，不是任意扩大数据集的扫描服务。缓存有磁盘增长成本；S2 必须补容量策略。人工复核、自然污染结果不能由脚本替代。发布和对外效果宣称需依据实际收据。

## 首阶段操作

现有命令 `node tools/cli.mjs audit --root DATASET --out NEW_OUTPUT --cache CACHE --include-orb` 会复用 ORB 特征和已完成的方向检查。恢复使用相同缓存、新输出目录及相同源数据；工作预算作用于本次新增计算，报告逻辑工作量含复用。缓存仍需当前文件校验与解码，不自动突破像素和图片数上限。当前证据见 `reports/plan-0.9.0/README.md`。
