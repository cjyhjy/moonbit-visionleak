# 本地证据复核教程

VisionLeak 的浏览器工作台读取 CLI 实际生成的审计结果，不预填检测结果。示例数据是有已知来源关系的受控合成图像，不代表真实数据集发现了缺陷。

## 启动

在项目根目录安装依赖、构建核心后运行：

```sh
node tools/cli.mjs audit --root fixtures/benchmark --out reports/my-demo
node tools/server.mjs --report reports/my-demo/report.json --port 4173
```

浏览器打开 `http://127.0.0.1:4173/`。已有报告可直接用第二条命令。输出目录必须是新的目录；已有目录的覆盖规则见 CLI 文档。服务仅绑定 `127.0.0.1`，只读地提供固定前端文件、指定报告与对应缩略图。不要直接以 `file://` 打开 HTML；前端需要同源读取 `/report.json`。

## 复核步骤

1. 先看顶部扫描状态与「运行信息与覆盖范围」。`complete: false`、错误非空或失败状态均醒目标为不完整；即使当前没有候选，也不能据此排除泄漏。
2. 用证据等级、复核状态、split、路径搜索和最大 dHash 距离筛选队列。距离为 0–64 的汉明距离，不是概率。输入 `/` 可聚焦搜索框。
3. 点击图像对，查看两侧路径、集合、尺寸和缩略图。展开指纹可检查字节摘要、像素摘要、dHash、对比度与稳定 pair key。
4. 选择「确认关联」「排除关联」或「暂不确定」，再填写备注。标记与备注自动保存在本浏览器的 localStorage，以 auditId 分隔。人工标记不会改变机器证据等级或源文件。
5. 在「未复核」筛选下标记后自动续到后续证据；「下一待复核」在当前筛选中循环查找。顶部把未复核和暂不确定分别计数。「撤销上次标记」恢复之前的决定或未复核状态；编辑备注、导入或切换报告后撤销失效，避免覆盖新内容。J/K 切换前后证据，N 跳下一待复核；输入、输入法组合或修饰键期间不触发。撤销只作用于当前本地记录，不能撤回已经导出的副本；旧副本重新合并仍按时间规则处理。
6. 点击「导出复核」下载 `review.json`；点击「导出完整报告」下载保留全部原始字段并附加 `review` 字段的 `report-reviewed.json`。浏览器本地存储不是备份，换浏览器、端口、隐私模式或清理站点数据可能无法恢复，建议及时导出。

## 证据含义

| 等级 | 说明 | 复核边界 |
|---|---|---|
| 字节相同 | 文件字节一致 | 文件可能重命名；是否影响评测仍取决于任务与分组要求 |
| 像素相同 | 规范化后的像素一致 | 编码或元数据可以不同，规范化协议见报告 |
| 相似候选 | dHash 距离落在阈值内 | 低对比度、重复纹理等可能碰撞，绝不自动认定泄漏 |

所有图像对必须跨 split。工作台没有删除数据、修改图片或自动处理候选的功能。缩略图只供辅助查看，最终判断应结合完整源图与来源。

## 导入与报告隔离

「导入报告」接受 `visionleak-report-v1` JSON，并先核对内容摘要。内容被改变却保留旧 auditId 时整份拒绝，当前报告与标记保持不变。0.2.0 新增 canonical 身份算法，旧 0.1.0 CLI 报告仍兼容；附加 review 单独验证且不改变机器审计身份。无默认报告时显示空状态和文件选择按钮。导入另一 auditId 的报告后，页面禁用缩略图并提示使用该报告重启服务，避免从当前服务误取同路径旧图片。默认 `/report.json` 尚未成功读取时同样禁图。仅相同 auditId 的报告才能使用当前服务的缩略图。

「导入复核」接受 `visionleak-review-v1` JSON。整份文件必须通过 auditId、规范化 pair key、图像对存在性、唯一性、决定值、备注和时间校验；任一条不符就全部拒绝，不留下部分导入。有效文件与现有标记合并，同一 pair key 保留 `updatedAt` 较新的结论。导入完整报告中的 `review` 同样校验。

pair key 为左右图像 ID 排序后 JSON 编码的二元素数组，避免路径分隔符造成碰撞。支持的决定为 `confirmed`、`rejected`、`unsure`。备注上限 20,000 字符；浏览器单个 JSON 文件导入上限 32 MiB。

auditId 是审计身份绑定字段，不是数字签名、来源证明或真实性保证。内容校验只检测未同步摘要的改动；任何人都可以为自制报告计算新摘要，同 ID 或相同指纹不能替代对源文件的独立核验。服务端对缩略图做摘要检查也不使任意导入报告获得真实性保证。

```sh
node --test tests/demo-validation.test.mjs

```

测试覆盖防串案、原子拒绝、指纹距离范围、错误覆盖完整性状态、相同 ID 以外禁图、筛选与报告/复核往返。浏览器验收状态和执行限制见 `demo/qa/verification.json`；截图仅是对应运行时的布局与交互证据，不是完整评测结果。

## 0.3.0 水平镜像模式

CLI 增加 `--include-mirrors`；JS `fingerprint({width,height,rgba,includeMirrors:true})` 或核心 `fingerprint_mirrored_rgba` 额外返回 `dhashMirror`。核心审计传 `options.includeMirrors:true` 时每个图像必须提供有效 `dhashMirror`。报告中的非原方向 `matchTransform` 对应 left/right 的水平反射，仍属人工复核候选，不能当作像素相等。默认模式不计算额外镜像指纹。详见 [0.3.0 合同与评测](changes-0.3.0.md)。

## 0.4.0 照片评测与直角旋转
