# 设计、资源边界与局限

处理链为：只读扫描 split → 有界解码 → MoonBit 全分辨率规范化和指纹 → 精确摘要桶与 dHash BK-tree → 跨 split 成对证据 → 本地浏览器人工复核。没有模型调用、embedding 服务或隐式上传。

精确桶以原始文件 SHA-256 和规范化像素 SHA-256 为键，独立于感知索引。即使 API 调用方给出了不一致的 dHash，精确相等也不会被阈值过滤漏掉。同一张图可能同时命中字节桶和像素桶，逐项去重确保一对只输出一次。BK-tree 采用汉明距离三角不等式查询边 `[d-threshold,d+threshold]`，用显式栈遍历并逐次消耗预算。相同 dHash 存一个节点的成员列表。

0.2.0 将已验证的 dHash 一次性打包为两个 UInt32，精确桶和 BK-tree 内部通过两次 XOR + popcnt 求距离，避免每次节点访问重复验证和扫描字符串。JS 后端使用 32 位位运算，不经过可能丢失 64 位整数精度的浮点表示。此修改不改变指纹算法、阈值、查询和插入次序、预算计费或输出顺序；全位边界与独立穷举 oracle 回归覆盖两个字的符号位及第 32/33 位交界。前后完整报告与性能复现方式见 `docs/reproducibility.md`。

常规存储为 O(n + 输出对数)，不预先生成 n² 距离矩阵。但 BK-tree 在高阈值、相似哈希或某些分布上可能退化；精确重复大组也有平方级的有效证据对。`maxComparisons` 和 `maxPairs` 处理这种最坏情况；到限后返回已知正确的前缀证据和 `incomplete`。不声称近似索引总是次线性，不声称能够在固定预算内审完任意规模数据。

MoonBit 规范化复杂度为 O(像素数)，bytes API 至多 4,194,304 像素，另外持有原始 RGBA、有界 canonical RGB 块、灰度与解码缓冲。CLI 串行解码、关闭 sharp 缓存、限制单文件与累计像素；还限制目录层级、扫描项和图片数。预算不是操作系统级的硬内存隔离，native 解码库内部分配不由 MoonBit 计量；请只处理可合理获得的文件并留足内存。

默认仅审计 train/validation/test 内支持扩展名的图片；不读取标注、标签、拍摄主体身份或原始采集会话。报告记录缺失 split 和忽略文件计数。它可发现跨集合重复内容，但不能证明模型曾训练过这些数据，不能判断同一主体不同照片的语义泄漏，也不能推断上游实际划分过程。

CLI 在创建输出父目录前先解析最近一个已存在祖先的真实路径，再补回尚不存在的路径段，拒绝与数据集互为祖先或子目录的输出位置。因此，经符号链接指向数据集的输出路径会在 `mkdir` 前被拒绝，避免失败操作仍在源目录留下新建目录。创建父目录后还会重新检查解析后的输出位置；`--force` 不跳过路径隔离检查。

指纹对重新编码和适度缩放可有用，但灰度方向摘要没有颜色、语义和局部几何理解。纯色、同方向渐变会发生碰撞；裁切、镜像、旋转、遮挡、拼贴和严重编辑可能漏检。阈值 6 是可复现的演示参数，不是经大规模真实数据验证的最优阈值。公开照片补充若存在，也只有人为注入的变换真值，不能称公开数据集泄漏发现。

所有候选供人工复核。原始图像不修改；本地报告缩略图只供展示，不参与指纹和最终判断。默认复核记录存浏览器本地，并绑定 auditId；清理浏览器或换设备前应导出 JSON。服务器只监听 loopback，并对可服务路径设白名单。

新报告使用 `identityVersion: 'vl-report-sha256-v2'`：排除顶层 `auditId/createdAt/timing/review` 后，递归规范化对象键并保留数组顺序，再计算内容 SHA-256。浏览器和服务器均核对报告内容与身份，旧 0.1.0 报告按原 CLI 属性顺序算法兼容校验。内容摘要可防止意外改动后沿用旧身份和复核记录，但不是签名；掌握内容的人可以重新计算摘要，不能据此证明来源可信。详细字段合同见 `docs/api.md`。

交付包从一致的 Node/MoonBit 版本清单读取版本，0.2.0 使用独立 ZIP，保留已有 0.1.0 ZIP 与校验和。打包器拒绝用不同内容覆盖同版本归档。最终 ZIP 的解包执行结果记录在包外，避免自引用；验收先记录 `running`，包括缺失 ZIP 在内的失败改记 `failed`。成功后删除本轮临时解包副本，失败时保留已经创建的副本供排错，历史报告不代替新版本验收。

## 0.3.0 水平镜像模式

CLI 增加 `--include-mirrors`；JS `fingerprint({width,height,rgba,includeMirrors:true})` 或核心 `fingerprint_mirrored_rgba` 额外返回 `dhashMirror`。核心审计传 `options.includeMirrors:true` 时每个图像必须提供有效 `dhashMirror`。报告中的非原方向 `matchTransform` 对应 left/right 的水平反射，仍属人工复核候选，不能当作像素相等。默认模式不计算额外镜像指纹。详见 [0.3.0 合同与评测](changes-0.3.0.md)。

## 0.5.0 大图路径（已完成阶段验收）

完整源图默认最多 64MP、硬上限 100MP；独立的感知像素上限仍为 4194304。超过感知上限时，MoonBit 按行块完成与既有 VL1 域一致的完整像素摘要，sharp 从原编码输入重新取得有界感知图。报告分别声明原图尺寸、pixelDigestBasis 与 dhashBasis。字节摘要始终针对原编码文件，精确重复不会因取样而升级或降级。

增量哈希只保留一个 64 字节 SHA 块及一个调用方大小的规范化 RGB 块；主机解码仍保留一次完整 RGBA，native 解码库与 GC 还会分配其他缓冲。本机 12MP 实测的时间与峰值 RSS 在阶段报告中，不作为所有图像、格式和机器的资源保证。

历史实现冻结保留在原文件，0.4.0 检测基线另存 `research/photos-v1/freeze/0.4.0.json`。后续优化比较 pairs/groups 的完整序列，差异默认失败；stats 与计时只列差异。显式允许检测变更必须提供理由，差异仍写入输出。现有 0.4.0 保留来源组后续仅作为回归集，不能重新用于调参后仍声称是全新保留组。

## 0.5.0：局部证据与审计策略

MoonBit 通过规范化灰度积分图对 20 个固定矩形取 9×8 网格，再计算 dHash。积分图只建立一次，避免每个窗口重复遍历原图。每个窗口仍使用普通汉明距离；局部索引与全图索引分开，不把非度量的最小窗口距离当作 BK-tree 边长。

局部查询先保留已有精确/全图结果，只对未发出的跨 split 配对给出首个阈值内窗口见证。局部边不合并确定性组件；比较和输出预算仍统一生效。默认关闭时不建立局部索引，不改变八个旧回归模式的检测结果。

关卡、复核比较、coverage、候选组件和 CSV 建议均由 core/workflow.mbt 决定。Node 只负责安全文件读取、解码、写报告和界面适配。

## 0.6.0 索引与扫描优化

半径至多 7 时，大树采用 MIH 候选及祖先标记预筛选，保持原 BK-tree 遍历次序和完整审计的局部窗口见证。新增索引操作独立预算；截断位置与统计可以变化。指纹摘要使用有界 RGB 块，开启裁切时共享灰度转换。当前完整性能证据、实验性 v2 未启用的原因及仍存在的解码限制见 [优化记录](optimization.md)。
