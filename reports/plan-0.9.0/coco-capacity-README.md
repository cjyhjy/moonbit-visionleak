# 100/1000/5000 真实照片生产链路容量

[冻结协议与数据链](../../research/coco-capacity-0.9.0/README.md)，汇总为 `coco-capacity-summary.json`。使用全部5000张COCO val2017，按预定顺序取前缀、奇偶人工split；最长边统一至384px且不放大。所有原图字节及原始RGB摘要均不同。关系没有污染标签，不能从容量输出推断精确率或召回率。

这是固定机器上的单次探索测量。Core保留默认算法/阈值6，但输入、像素及比较容量显式提高，并非CLI全默认参数；检索模式显式开启ORB及近似检索，每次最多20亿描述子比较、1亿posting访问、ORB300秒及两个独立256MiB子进程RSS护栏。冷/恢复总耗时包括反复宿主准备、源文件/缓存校验、Core和缩略图等，不是纯匹配或特征提取CPU时间，也没有统计加速比保证。各规模使用独立缓存，冷热共享主缓存，中断恢复另用新缓存；阶段顺序执行，无并行CI干扰本表测量。

5000图有3890405条描述子；原应检6249994个跨集合配对，选择4980对并完整验证，实际9958次几何方向检查、12138836108次逻辑描述子比较，跨10次有界调用推进。索引实际访问341918157次、最终逻辑访问341757949次，边界未完成查询产生的少量重做没有抹去。热运行命中特征5000份，新增方向检查0，最终auditId与冷及真实中断恢复一致。返回6个Core候选及4个ORB候选，均不在本试验赋予污染真值。

5000图的主Node独立调用OS高水位峰值约447.1MiB，ORB子进程100ms采样峰值约75.9MiB，索引子进程约226.8MiB。不可把这些峰值相加冒充同步进程树峰值；宿主未设置RSS硬护栏，锁进程和外部研究驱动也不在子进程RSS预算中。主缓存逻辑文件442.7MiB、文件分配约498.2MiB（含非ORB命名空间/锁文件，不含目录元数据），不等于ORB分片载荷配额。

所有候选队列完成，所有最终检索报告仍 `complete:false` / `exhaustivePairsComplete:false`、`ORB_APPROXIMATE_COVERAGE`、gate exit2，因为粗筛省略配对。三个规模的完整报告均经身份/输入/覆盖/热零新增几何检查核验，各有independent-report-verification.json，均绑定最新生产CI源码摘要cb0bfa505359fd70fb6704b87a33ee17c5c2a464522fc8e21bf9d27e1f6f2f56。

真实崩溃发生在新缓存已有至少32条提交ORB记录后，保留SIGKILL、特征复用及相同最终身份。预算续跑另外验证查询、方向和完成前缀复用；本轮不声称覆盖5000图索引/几何行中途SIGKILL的全部压力情形。

失败也保留：初始驱动导入错误见coco-capacity-100；首次真实5000照片在第1912张遇到OpenCV返回801点，见coco-capacity-5000/failure.json。修复硬上限后所有新缓存重跑目录以cap-fixed结尾。cap-fixed结果不能与失败前的100/1000结果混用成同一源码容量表。CI-feature-cap为30项通过、Node83项零跳过；既有71几何见证及168图特征摘要回归也通过。

原图合计1368653453像素，超过当前maxTotalPixels硬上限10亿，因此未将统一缩放输入冒充全原始分辨率5000图验收。全原尺寸输入/预算策略、纯特征与纯几何计时分解、更多性能重复、Linux、发布包及浏览器文件迁移全流程仍保留在待办。自然效果以独立的CIFAR标签研究为准，真人耗时仍未测量。
