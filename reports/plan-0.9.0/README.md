- `phases.orb.pairChecks/descriptorComparisons` 表示本次输出覆盖的逻辑工作，含已缓存工作；`timing.orb.executedPairChecks/executedDescriptorComparisons` 是本次执行量，工作预算约束后者。复用计入 `featureCacheHits/matchCacheHits`。输入像素等原有预算依然生效；重新运行仍解码、核验源文件。

## 第三轮更新：OS锁与持久前缀

当前缓存格式改为orb-v3，前述orb-v2/PID写锁是历史实现。锁由独立的最小Python进程持有fcntl OS文件锁；父进程退出导致stdin EOF，或锁进程死亡时自动释放，避免并发回收PID锁的竞争。独立写入者竞争同一分片、写入者被SIGKILL以及并发配额检查均有真实进程测试；没有把锁文件删除当作释放机制。锁进程不读取图像/特征，其RSS不计入原有ORB worker采样峰值。

每完成一张输入的配对遍历，就提交一个持久前缀及命中引用。恢复时重新核验图片和特征，然后装回有效命中、跳过前缀内的配对遍历。未完成行仍按方向结果缓存推进。缺失命中引用会使前缀整体失效，回退后补算并保持最终auditId一致。该行为在真实ORB回归中验证；它没有免除源文件检查，也不代表任意配对游标或分布式任务队列。

v3的100/1000/5000张派生图片特征阶段冷/热复验见batch-capacity-v3.json，全部达到预定特征数量并按0匹配预算停止；5000张冷26390ms/热11002ms，热特征命中5000。此轮与完整CI并发运行，仅作容量/功能证据，不能据此作独立性能比较。完整审计规模、自然数据效果与真人复核边界仍然保留。

第三轮最终验收为ci-cursor/verification.json：30项通过，Node72/72零跳过，MoonBit三后端/native release各83项通过；归档后sourceDigest复核一致。前述ci/为第二轮历史收据。当前状态见STATUS.json；第三轮通过也不代表完成0.9.0发布门槛。
